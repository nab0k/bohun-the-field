# C3-10: проверка независимого аудита Antigravity (07.11.2026)

**Источник замечаний:** полученный от владельца отчёт Antigravity в режиме чтения. **Область:** только PR #196, ветка `chatgpt/C3-10`. Результаты ниже сверены с файлами `core.py`, `identity.py`, `stages.py`, `metrics.py`, `test_core.py`, README и существующим логом локального запуска. Это не принятие C3-10 и не одобрение публикации.

**Вердикт по ГОТОВНОСТИ К ПРОДАКШЕНУ: FAIL, согласны.** У редактора нет доверенного источника `SemanticAssessment` и `retrieval_verified`, проверенного полного каталога опубликованных событий, atomic publisher compare-and-swap и результатов на размеченных реальных случаях. Но Antigravity смешал эти пробелы с дефектами офлайн-прототипа и рядом ошибочных описаний текущего кода.

## Разбор C1–C9

| ID | Проверенный вывод | Действие |
|---|---|---|
| C1 — `ModuleNotFoundError: collectors` | **Ошибка среды запуска, а не доказанный дефект импорта.** `collectors/editor/__init__.py` существует; тесты используют `from collectors.editor ...`. Для `unittest discover` нужен корень репозитория в `PYTHONPATH`. Импорт с произвольной рабочей папки закономерно может не работать. Ранее полный набор из 97 тестов прошёл в изолированном запуске, лог передан владельцу. Аудит Antigravity зафиксировал 3 ошибки импорта, не 3 упавших тестовых сценария. | Добавить в README точные команды из корня копии для POSIX и PowerShell. **Не** внедрять `sys.path.append('..')` в библиотеку и не писать `pyproject.toml` вне разрешённой папки. |
| C2 — IDN/punycode «блокируется» | **Не подтвердилось.** `ip_address(host)` при домене выдаёт `ValueError`, который намеренно обрабатывается, затем доменная ссылка считается синтаксически допустимой. Отдельно локально проверены `xn--...`, Unicode IDN и `127.0.0.1`. `rstrip('.')` нормализует завершающую точку FQDN; эта операция не меняет punycode-метки. | Добавлены регрессии для IDN и локального IP. **Не** утверждать, что URL сетево существует: проверяется только синтаксис. |

Для реального выпуска нужен доверенный адаптер, а не булев флаг от неавторизованного клиента. |
| C4 — нет `baseline/falsifier` | **Отчёт неверен в части получения PASS.** Без любого поля сигнал получает REVIEW (`E13` / `E15`), не PASS. | Не превращать автоматически в BLOCK до измерения false BLOCK на хорошем корпусе и утверждения политики. |

Нестандартный вход необходимо преобразовать **до** финального gate; иначе возникает неоднозначность опубликованного payload. | Оставить схему; добавить адаптер при интеграции с реальным producer. |

Но предложенный `if published and any(...)` по смыслу **уже реализован** циклом; `E20 BLOCK` по совпадению `material_id` сломал бы корректные новые версии того же материала. | Перед реальным PASS publisher должен получить полный авторитетный snapshot/индекс дублей, его версию/время и транзакционно проверить неизменность. В офлайн-прототипе этого ещё нет: `offline_only=True`. Не объявлять проблему исправленной. |

## M1–M4 и N1–N3

- **M1:** тройные кавычки docstring в `core.py` **закрыты** до `from __future__`. Ошибка подсветки не воспроизводится.
- **M2:** **подтверждено**: прежний regex разбивал `1 000` и `1 000` на отдельные числовые токены и мог ошибочно заблокировать `1000` при доказательстве `1 000`. **Исправлено**: группировка тысяч через обычный пробел, NBSP (U+00A0) и NNBSP (U+202F). Добавлены 4 числовые регрессии, включая неправильное число, которое должно оставаться отклонённым.
- **M3:** `mailto:` как значение **поля URL** уже не проходит `_url_ok` (разрешён только HTTPS). Произвольный `mailto:` в обычном тексте сам по себе не является первоисточником; не блокировать автоматически.
- **M4:** `check_stage_assertions` уже явно валидирует list/tuple, stage, source/span, event ID и даты; заявление об исключении без воспроизведения не доказано. Остаются недоказанными семантическая истинность стадии и доверенность источника.
- **N1:** в README дополнена инструкция по рабочей папке и `PYTHONPATH`.
- **N2:** размер проверяется в байтах именно **канонического JSON**, который хешируется, а не строкового `repr`; это консистентно с pin.
- **N3:** `_hash(asdict(policy))` вызывает `_canonical`, а она сортирует ключи. Неконсистентность сериализации отсутствует.

## Блокеры до приёмки C3-10

1. **Trusted provenance:** `retrieval_verified`, `coverage_complete` и `checker_model_id` сейчас могут быть подделаны вызывающим кодом. Нужен доверенный, независимый adapter с fail-closed политикой, которому доступен окончательный payload и точные цитаты.
2. **Полный snapshot дедупликации:** отсутствие записи в пустом `published` не доказательство отсутствия дубля; проверка должна быть атомарной на стороне источника истины, включая обновление версии материала.
3. **Publisher CAS:** `EditorVerdict.matches()` только сравнивает локальные SHA/ID/policy; это **не** атомарное разрешение публиковать. До publisher CAS никакой локальный PASS не даёт права на выпуск.
4. **Проверка на размеченном корпусе:** четыре согласованные предварительные метрики 99/85/5/20 ещё не оценены на holdout. Текущие тесты синтетические и не доказывают эти пороги.

**Решение:** PR #196 остаётся Draft; правки ограничены `collectors/editor/`, workflow/main/production не затрагиваются. Общее заключение Antigravity «FAIL для промышленного gate» сохраняется, но список обязательных исправлений должен опираться на доказанные дефекты, а не на неподтверждённые предположения.
