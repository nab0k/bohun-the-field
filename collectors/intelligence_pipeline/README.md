# EXP-009 — выбранный runtime INPUT29

Локальный кандидат, **не развёрнутый облачный MVP**. Один выбранный путь:
`Inoreader/web → source snapshot → context → extract/analyze/review + dossier → Notion`.
Канонический CLI — `scripts/intelligence-pipeline.py runtime`; cloud mode —
`pipeline` в `.github/workflows/inoreader-trials.yml`. Версия config/лимитов:
`exp009-runtime-input29-v3`. Старые AUTO08 config и cloud-кандидаты с другим RPC
не совместимы с этим запуском и не подставляются как fallback.

## Исполнение и деньги

Основные adapters: верхнеуровневые `runtime.py`, `postgres.py`, `gemini.py`,
`notion.py`, existing Worker/contracts, bounded `retrieval.py` и source adapters.
`costing.py` фиксирует Standard text цену INPUT26 в целых microUSD: $0.30/M input,
$2.50/M output включая thoughts, округление вверх на запрос. Это версия цены
для первого испытания, не автоматическая подписка на будущие цены.

`model_access` в config содержит `account_scope`, `reference`, `key_sha256`,
`expires_at`, `mode`; для CAPPED_PAID также `cap_micro_usd` в диапазоне1..1000000.

- `FREE_ONLY`: требуется отдельное подтверждение доступности бесплатного аккаунта
  для этого ключа/scope/срока; в постоянной конфигурации денежный cap=0, действуют
  общие request/token ceilings. API key/Standard tier сами по себе free не доказывают.
- `CAPPED_PAID`: нужен отдельный явный допуск конкретного запуска. Общий cap≤$1,
  без reset при перезапуске или полуночи. Запись approval в config не выдаёт
  владельческое разрешение на модельный вызов.

Режим не выбирается автоматически. Перед сбором для модельного run сверяются
постоянные mode/key/approval/model/price/cap/expiry. Перед HTTP — полный резерв,
затем dispatch. UNKNOWN удерживает резерв; actual usage включает thoughts.
Неполные metadata, неверный model/tier/STOP/tools блокируют принятие ответа.
Счётчики/бюджет в Python doubles проверены offline; новая SQL-версия требует
отдельного PostgreSQL испытания. Старый INPUT28 PASS на новые bytes не переносится.

## Источники и аналитика

Существующие Inoreader и web extractor не заменены вторым сборщиком.
Допуск остаётся связан с проверенной политикой и hash текста. Наличие body
не подтверждает полноту, права или безопасность. В source_adapters сохранён
параллельный незавершённый код admission profiles AUTO09; INPUT29 не подключает
его автоматически к SQL и не объявляет проблему новых материалов решённой.
Это остаётся blocker автономного дня и требует отдельного просмотра правил.

Контекст — до4 записей, общий bounded объём, quote/hash/time/status; company lead
не становится verified. Досье сохраняет before/after, тип изменения, наблюдения,
гипотезы с альтернативой/проверкой/опровержением/датой пересмотра и пробелы.
Структурная проверка не доказывает смысловую истинность или экономическую пользу.

## Доставка и публикация

Версионная очередь захватывает PENDING перед POST и выдаёт fencing token.
Второй worker не создаёт страницу; просроченный SENDING становится UNKNOWN.
Timeout/lost acknowledgement не повторяет POST; recovery только читает и сверяет.
Прочитанное расхождение даёт CONFLICT, человеческая страница не изменяется.
Маркер включает hash всего packet, в том числе dossier/context, дополнительно
к prose/version hash. Результат остаётся PROPOSED / QA HOLD / public_release=false.

Сайт/карта используют отдельные editorial/QA/exact-version public_release gates.
Локальный projection/preview не является подключённой или опубликованной лентой.

## Выбранный состав и внешние шаги

Для будущего коммита нужен reviewed core/source/retrieval/web dependency состав,
а не только diff13paths INPUT29. Каталог `cloud/`, `scripts/intelligence-cloud.py`
и `intelligence-cloud.yml` сохраняются как **невыбранная локальная альтернатива**;
их не включать в выбранный deployment bundle и не provision BOHUN_ANALYSIS_DSN.
INPUT29 не вызывает их transport/coordinator и использует BOHUN_RUNTIME_DSN.
Наличие оставленного workflow в рабочей папке не означает, что он отключён на
GitHub; внешнее состояние не проверялось/не менялось этим локальным этапом.

Новый SQL — приватный `UNIFIED_STORAGE_INPUT29.sql` в общей папке эксперимента,
не db/migrations и не public. Сначала rollback rehearsal нового exact hash,
затем отдельно permanent apply/ограниченные credentials/source policies/Notion
parent/model run. После результата — согласованные Git/cloud/schedule и
подтверждённый самостоятельный запуск без Mac; затем сайт/карта/release/rollback.
Режим pipeline workflow manual-only, dependencies только в RUNNER_TEMP venv.
Локальный G3 не устанавливает пакеты, не вызывает сеть и не запускает workflow.

Ниже сохранено описание исходных A18/AUTO-02 memory/replay этапов. Их ограничения
относятся к этим этапам; живое качество и автономный день ещё NOT_RUN.

## Что реализовано

| Файл | Назначение |
| --- | --- |
| `contracts.py` | Документ/событийная стадия/утверждения, версии контрактов, source hash, стабильная идентичность, ограничения входа, структурные проверки |
| `ports.py` | Интерфейсы модели, общего бюджета и атомарного хранилища, включая получение/завершение задачи и fencing истёкшего lease |
| `worker.py` | Один ограниченный проход `extract → analyze → review → EDITORIAL_READY` либо HOLD/отложенная задача |
| `quota.py` | Эталонный бюджет в памяти: суточные UTC резервы всех запросов, неопределённый расход, фактический перерасход и остановка |
| `editorial.py` | Эталонные версии/решения в памяти: человеческая правка не затирается машинной, решение связано с конкретным hash |
| `testing.py` | Эталонное хранилище в памяти и воспроизведение **заранее supplied** модельных ответов, без вызова модели |
| `routing.py` | Отдельный pure отбор до 50 явно переданных источников → до 5 исследовательских кандидатов, причины и две оси достаточности/релевантности |
| `research_packet.py` | Неизменяемый вход исследования: версии/тексты/hash, буквальные фрагменты, кандидатские сущности, вопросы/пробелы; без I/O |
| `../../scripts/intelligence-pipeline.py` | Исходный offline replay и отдельный opt-in runtime AUTO-08 |

Документам с прежним текстом/существенными метаданными не нужны повторные запросы;
новый источник-алиас сохраняется отдельным receipt. Изменение текста или версии
конвейера создаёт новую задачу. Канонизация URL убирает только tracking-параметры;
значимые query arguments сохраняются. Сходство заголовков не объединяет события.

`verified_entity_ids` поступают только из доверенного проверенного каталога
будущего адаптера. Ответ модели не может сам подтвердить компанию. Нет сущности,
к которой относится утверждение, — допустим `not_applicable` без company ID;
неоднозначная или кандидатская связь удерживается. Стадия `announced/planned`
не превращается по ответу модели в `signed/delivered`.

Структурные проверки ловят несуществующую дословную цитату, изменённые числовые
литералы, чужие claim IDs/hash, неизвестные поля, подмену типизированной стадии.
**Они не доказывают смысловую истинность**, качество экономического вывода,
достоверность самого источника или полноту сведений. Source stage/rights и
каталог на этом этапе — явно заданные тестовые входы, не автоматически проверенные
факты. Контекстный поиск пока не выполнен, это отмечено в редакционном пакете.

## Очередь, квота и повторы

Будущий облачный Store должен транзакционно сохранять результат и следующую
задачу; сравнение token/expiry не даёт опоздавшему работнику записать результат
после передачи задачи другому. `MemoryStore` проверяет этот контракт в пределах
процесса и **не является сохранением состояния после перезапуска процесса**.

Общий budget scope относится к аккаунту. Перед каждым модельным вызовом нужен
ненулевой резерв полного входа, выхода/reasoning и compute units. Неопределённый
расход после исключения не возвращается: новый вызов требует отдельного резерва.
Измеренный перерасход сохраняется и замораживает день. Завершение запроса после
полуночи относится к UTC дню его резерва. Ожидание следующего дня из-за квоты не
исчерпывает число модельных повторов. Ретраи ограничены, бесконечного цикла нет.

Это **не гарантия exactly-once внешнего inference или денежного hard cap**.
Если процесс погибнет между модельным запросом и сохранением ответа, повтор
может стоить дополнительного вызова. Нужны persistent reservation/request IDs,
reconciliation и подтверждённые провайдерские ограничения. В `MemoryQuota` нет
общего состояния между отдельными запусками/машинами; её нельзя ставить вместо
Supabase ledger в облаке. Production-токенизация, тарифы и оценка Neurons пока
не реализованы; числа synthetic fixture не являются measured provider usage.

## Редакторский и публичный выходы

`EDITORIAL_READY` означает готовый **кандидат для человека**, не QA APPROVE.
Пакет содержит текст, почему важно, альтернативы/неизвестное, claims/цитаты,
источник/даты/hash, происхождение и предупреждения. Same-model review не является
независимым QA. У всех пакетов `qa.decision=HOLD`, `public_release=false`.

`MemoryEditorial` хранит неизменяемые версии. Человеческая правка требует
ожидаемый текущий hash; параллельная правка/устаревшее решение вызывают конфликт.
Новая машинная версия остаётся предложением, если уже есть человеческая редакция.
Выбор утверждённой публичной версии/отзыв публикации остаются задачами будущего
транзакционного release-адаптера: передавать старое решение вместо актуального
нельзя. Будущий Notion adapter обязан отдельно решать неоднозначный create и
гонки rich-text; этот код не обещает Notion compare-and-swap.

`public_projection()` — чистая проверка контракта допуска, по умолчанию выключена.
Требует отдельно доверенный QA receipt, совпадение version/hash, редакторское
решение и явный public_release, права и безопасный материал. Модель не получает
этого интерфейса/полномочия. Положительные вызовы есть **только в тестах**;
CLI никогда не включает выдачу. Это не замена `src/qa/m0-gate.mjs`, не калибровка
автоматической публикации и не готовый payload существующего UI/API.

## Проверка без сети

Из корня репозитория, установленным Python 3.13+:

```sh
/opt/homebrew/bin/python3.13 -B -m unittest discover -s tests/intelligence_pipeline -v
```

CLI принимает JSON с точными ключами `mode`, `documents`, `responses`, `limits`:

- `mode`: только `synthetic-replay`.
- `documents`: 1–100 синтетических документов по контракту Document.
- `responses`: словарь `<document.identity>:<extract|analyze|review>`; запись
  содержит заранее подготовленный `payload`, `estimate` и `usage`. Все usage
  поля — неотрицательные целые `input_tokens`, `output_tokens`, `compute_units`.
- `limits`: `requests` и общий `usage` по тем же измерениям.

Пример формирования входа и проверки CLI есть в
`tests/intelligence_pipeline/test_pipeline.py`, `CLITests`. Воспроизведение:

```sh
/opt/homebrew/bin/python3.13 -B scripts/intelligence-pipeline.py \
  --input /private/tmp/exp009-synthetic-input.json \
  --report /private/tmp/exp009-synthetic-report-UNUSED.json
```

Пути — примеры: сначала нужен подготовленный вход. Отчёт создаётся исключительно
новым файлом с mode 0600 **вне Git checkout**, без вывода текстов в stdout. Не
класть реальные источники/Notion-снимки в публичные artifacts, logs, public/dist
или Git. CLI ограничивает вход 5 MiB, не повторяет отложенные задачи в цикле и
не открывает сеть. Memory state начинается заново с каждым replay.

## AUTO-02: отбор и Research Packet

`route_batch(records, rules=DEFAULT_RULES, packet_limit=5)` принимает только
список/tuple уже сохранённых `SourceRecord` (не более50), не URL для скачивания.
`RoutingResult.to_dict()` сохраняет категории/буквальные совпадения, все причины,
receipts, выбранные ключи, недобор и распределение источников. Не выбранные из-за
лимита кандидаты явно получают `DEFERRED_PACKET_LIMIT`.
`result.packets()` готовит неизменяемые входы следующего исследования.

`DEFAULT_RULES` — начальный версионированный словарь девяти широких групп,
включая производство, технологии, контракты, инвестиции, гранты/R&D, стартапы,
мероприятия, регулирование и исследования. Допустимы несколько категорий и
UNKNOWN. Совпадение слова означает кандидатский тип, а не доказанное событие.
Это не проверенный промышленный классификатор: словарь/языки/пороги ещё требуют
калибровки. Round-robin по явному порядку категорий уменьшает перекос внутри
партии; при лимите5 первые категории сохраняют преимущество. Суточной ротации,
производственного score и доказанной разнообразной дневной очереди здесь нет.

Права/полнота/чувствительность — явные входные сведения, не вывод из наличия
текста. Неизвестное/неполное требует проверки, запрещённые права/чувствительность
удерживаются. Metadata-only может стать наводкой, но не пригодным пакетом.
Кандидатские company IDs никогда не становятся verified; неоднозначная связь
удерживается. `SourceRecord.to_document()` допускает только пригодное основание
и передаёт пустые trusted IDs. Это вспомогательное преобразование, не подключение
пакета к Worker: нового облачного маршрута/задачи этот этап не создаёт.

Ключ источника включает source/version, canonical URL, title, text hash, дату,
стадию и evidence flags/кандидатские связи. Receipt time/item alias/tracking URL
сохраняются отдельно, не меняют смысловой ключ. Одна объявленная версия с разными
данными получает HOLD `SOURCE_VERSION_CONFLICT`; разные версии/URL не сливаются
по сходству заголовка. Полноценный междокументный StoryGroup ещё не реализован.

`build_packet()` принимает lead и необязательный **явно supplied** context,
evidence/previous_state, questions/unknowns; история/контекст не загружаются сами.
Не более5 источников, суммарно128KiB UTF-8 source text, до512KiB всего JSON с
цитатами/receipts; превышение отвергается без обрезки. Фрагменты проверяются по
точному hash и Unicode code-point offsets в переданном сохранённом тексте,
не в HTML/PDF. Без явного фрагмента по умолчанию сохраняется whole-text excerpt;
он не называется утверждением или подтверждённым фактом.

ID пакета учитывает задание/контекст/полный hash конфигурации правил. JSON выдаёт
отдельные `core`/`receipts`; изменение копии dict не меняет объект. Permissive
JSON import отсутствует: будущий boundary adapter должен восстанавливать строго
валидированные records, а не доверять присланным `qa`/hash. Сериализация сама по
себе не подпись и не право на исполнение.

Без прошлого основания явно указано `NOT_RETRIEVED; CHANGE_NOT_PROVEN`, с
переданным основанием — только `SUPPLIED_ONLY`. Все выходы QA HOLD,
public_release=false, execution DISABLED; будущий режим AUTOMATIC_WHEN_ENABLED
не требует ручного запуска каждого сюжета. Лимиты внешних страниц/модели по
умолчанию0, даже ненулевой лимит не разрешает внешние вызовы. Нет retrieval,
аналитического досье/статьи, DB adapter, Notion bridge или нового расписания.

Содержательные отрицательные проверки — `test_routing_packets.py`, запускаются
той же unittest-командой выше вместе с прежними тестами ядра. Только synthetic
данные; успешный прогон не доказывает качество пяти реальных сюжетов,
облачную автономность или достижимость10–20 материалов/3–4 часов редактуры.
