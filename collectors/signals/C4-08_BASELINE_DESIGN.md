## Реализованный дизайн

```text
Candidate(entity, metric, unit, kind, stage, as_of, target_value)
  |
  +--> injected read-only SQL adapter -> knowledge.edge [lead]
  |      enough verified, comparable evidence? --> return baseline
  +--> injected HTTP POST adapter -> USAspending recipient [lead]
  |      only for annual_total federal_obligations in USD
  |      enough verified, comparable evidence? --> return baseline
  +--> injected free-search adapter -> ranked web leads, max 2 queries
         |
         independent verifier (not provided) checks primary document,
         value + quoted span + date + URL + same unit/kind/stage
         |
         found | needs_verification | not_found
```

**Fail-safe:** все три адаптера отсутствуют по умолчанию, нет подключения к DB, нет сетевого клиента, не читаются secrets/env; `discover()` возвращает `not_found` и маршрут `not_connected`. Параметризованный SQL только `SELECT`; чтобы обеспечить режим чтения, при будущем подключении нужен отдельный DB-role с `SELECT` и `default_transaction_read_only=on`. Защиту нельзя обеспечивать одним текстом SQL, если сервису передали привилегированный DSN. Выход `Evidence` содержит значение/дату/цитату/ссылку/где искали/причину сопоставимости и признак `verification`; до проверки первоисточника это **кандидат**, не подтверждённая база. Пустые поля честно остаются пустыми. Поиск не принимает решения о сигнале.

### Технические оговорки

1. **Нет автоматического извлечения достоверного числа из `what`.** Свободный текст статьи возвращается как lead; `verify` должен подтвердить число, единицу и временной период по первоисточнику и только затем поставить `verified`. Для исправной интеграции нужен согласованный проверяющий, но это не часть C4-08.
2. **USAspending API показывает расходы/обязательства, а не выпуск ESSM, передачу техники или физические поставки.** Не сопоставлять `USD` с `units/year`, договор с поставкой и годовой total с темпом. На текущем этапе реализован узкий recipient-запрос **за прошлый календарный год** как lead, поскольку календарный и федеральный финансовый годы отличаются. Проверять фильтры, coverage, identifier `recipient_id`, период, смысл `amount` и цитату по award detail; непроверенный агрегат не станет baseline. `awarding_subagency` описан ниже, но автоматически **не вызывается**, так как нет подтверждённого agency filter и нельзя выдавать общие суммы агентства за сумму конкретной компании.
3. **Временной срез:** `as_of` обязателен. Теперь даже внешний `verify` не может провести `PASS` без `first_seen_at <= as_of` и даты значения `value_date <= as_of`; неподтверждённая дата доступности приводит к `needs_verification`. Это минимальная защита. Полный исторический backtest всё равно требует неизменяемого журнала первого появления источника и снимка доступных на дату поиска документов: передача фиктивного `first_seen_at` проверяющим не защищена криптографически.
4. **Source independence:** `root_source` объединяет перепечатки одного первичного заявления; количество веб-страниц не превращается в количество доказательств.
5. **География, объект и определение:** совпадение буквального `metric` и `unit` здесь необходимое, но **недостаточное** условие. Теперь код требует от `verify` явные `subject` (строго равен `entity`), `scope` (не пустой), `first_seen_at` и совпадение стадии, если стадия указана в запросе. Внешний `verify` всё ещё должен содержательно проверить применимый период, географию, numerator/denominator и первичность документа: свободный текст `scope` сам по себе этого не доказывает. Совпадение `value` в разных источниках само по себе не подтверждение.
6. Неявные API ошибки фиксируются как provider error, без вывода секретов или текста документов; при исчерпании лимита переход на следующий источник **только если это разрешено общим бюджетом**, иначе `not_found/needs_verification` с причиной. Никаких публикаций.

### Уточнение договора на будущие адаптеры

`sql_read(query, named_params) -> rows` возвращает **только** `what/occurred_on/source_url/status`. `post_json(url, json_body) -> response` (только allowlisted домен и endpoint, при интеграции ограничить timeout, retries, размер ответа). `search(query) -> [{title,snippet,url,origin_url?}]`, максимум две поисковые строки и до пяти lead на каждую. `verify(candidate,evidence)` возвращает evidence с нормализованным `value`, `value_date`, `quote`, `url`, `verification=verified` только после **внешней** проверки исходного документа. Для production нужна ещё проверка `first_seen_at` и provenance, которую нельзя имитировать из сегодняшних результатов.

Пример JSON-выдачи при пустой интеграции: `{"candidate_id":"s1","baseline":null,"alternatives":[],"searched":[{"provider":"knowledge.edge","status":"not_connected"},{"provider":"USAspending","status":"not_connected"},{"provider":"free_web","status":"not_connected"}],"outcome":"not_found"}`. Это не ложный сигнал и не пустой успешный baseline.

## Условия проверки, лимиты и принятие

- Предварительный программный бюджет на **1 кандидат**: max 1 локальный SELECT (20 строк), max 1 recipient POST (до 5 ответов), max 2 бесплатных web-запроса (до 10 ссылок). `MAX_API_REQUESTS=2` зарезервирован как верхний проектный лимит для развития subagency; сейчас не более 1. **Никаких автоматических HTTP вызовов:** transport предоставляется извне только после отдельного решения.
- Для `awarding_subagency` будущий адаптер требует verified agency filter и описание того, что именно сравнивает (расходы субагентства, не производителя). Сначала проверить карточку agency, затем тест запроса с фиктивным HTTP transport. Запрос по одному ключевому слову типа `minehunting` не считать подтверждённым baseline.
- Тест: группы из C4-02 (количество и детали доступны только Claude в локальном архиве), на большинстве кандидатов **подтверждённая сравнимая база** либо полный маршрут поиска и объяснение отсутствия. Отдельно проверить ESSM tempo, прошлогоднее award vs нынешний год, `announced/contracted/delivered/demonstrated`, годовой темп vs накопленная сумма, независимые roots.
- Реализованы offline mocks; **живые тесты, запросы к БД/USAspending/Tavily/Brave и workflow не запускались**. Данные ручной пробы не считались независимым live-тестом этого кода. Тесты могут запускаться локально стандартной библиотекой после ревью: `python -B -m unittest discover -s tests -p 'test_c408_baseline_discovery.py' -v`.

**Граница сдачи:** дизайн и изолированное ядро готовы к ревью. C4-08 по плану **не может считаться проверенной** до теста на группах C4-02 с настоящими evidence. Не делать выводов о сигналах, не подключать API, не изменять рабочие файлы, не запускать workflow, не сливать PR.
