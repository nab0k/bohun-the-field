## Реализованный дизайн

```text
Candidate(entity, metric, unit, kind, stage, as_of, target_value)
  |
  +--> injected read-only SQL adapter -> knowledge.edge [lead]
  |      enough verified, comparable evidence? --> continue searching independent second root
  +--> injected HTTP POST adapter -> USAspending recipient [lead]
  |      only for annual_total federal_obligations in USD
  |      enough verified, comparable evidence? --> return baseline
  +--> injected free-search adapter -> ranked web leads, max 2 queries
         |
         built-in verifier checks caller-supplied primary document,
         literal quote + number/unit/date + URL + same unit/kind/stage
         |
         found | needs_verification | not_found
```

**Fail-safe:** все три адаптера отсутствуют по умолчанию, нет подключения к DB, нет сетевого клиента, не читаются secrets/env; `discover()` возвращает `not_found` и маршрут `not_connected`. Параметризованный SQL только `SELECT`; чтобы обеспечить режим чтения, при будущем подключении нужен отдельный DB-role с `SELECT` и `default_transaction_read_only=on`. Защиту нельзя обеспечивать одним текстом SQL, если сервису передали привилегированный DSN. Выход `Evidence` содержит значение/дату/цитату/ссылку/где искали/причину сопоставимости и признак `verification`; до проверки первоисточника это **кандидат**, не подтверждённая база. Пустые поля честно остаются пустыми. Поиск не принимает решения о сигнале.

### Технические оговорки

1. **Верификация числа по переданному первичному тексту:** свободный текст `what` и snippets остаются leads. Встроенный `verify_primary` извлекает число, указанное непосредственно рядом с единицей, проверяет дату и дословное присутствие цитаты в предоставленном тексте. Модель не имеет права выставлять `verified`. Внешняя сторона должна предоставить сам первоисточник и доверенные метаданные.
2. **USAspending API показывает расходы/обязательства, а не выпуск ESSM, передачу техники или физические поставки.** Не сопоставлять `USD` с `units/year`, договор с поставкой и годовой total с темпом. На текущем этапе реализован узкий recipient-запрос **за прошлый календарный год** как lead, поскольку календарный и федеральный финансовый годы отличаются. Проверять фильтры, coverage, identifier `recipient_id`, период, смысл `amount` и цитату по award detail; непроверенный агрегат не станет baseline. `awarding_subagency` описан ниже, но автоматически **не вызывается**, так как нет подтверждённого agency filter и нельзя выдавать общие суммы агентства за сумму конкретной компании.
3. **Временной срез:** `as_of` обязателен. Теперь даже внешний `verify` не может провести `PASS` без `first_seen_at <= as_of` и даты значения `value_date <= as_of`; неподтверждённая дата доступности приводит к `needs_verification`. Это минимальная защита. Сам флаг `primary` и дата `first_seen_at` являются заявлением передающей системы. Полный исторический backtest всё равно требует неизменяемого журнала первого появления источника и снимка доступных на дату поиска документов: передача фиктивного `first_seen_at` проверяющим не защищена криптографически.
4. **Source independence:** `root_source` объединяет перепечатки одного первичного заявления; количество веб-страниц не превращается в количество доказательств.
5. **География, объект и определение:** совпадение буквального `metric` и `unit` здесь необходимое, но **недостаточное** условие. Теперь код требует от `verify` явные `subject` (строго равен `entity`), `scope` (не пустой), `first_seen_at` и совпадение стадии, если стадия указана в запросе. Внешний `verify` всё ещё должен содержательно проверить применимый период, географию, numerator/denominator и первичность документа: свободный текст `scope` сам по себе этого не доказывает. Совпадение `value` в разных источниках само по себе не подтверждение.
6. Ошибки провайдеров фиксируются как provider error, без вывода секретов или текста документов; при исчерпании лимита переход на следующий источник **только если это разрешено общим бюджетом**, иначе `not_found/needs_verification` с причиной. Никаких публикаций.

### Уточнение договора на будущие адаптеры

`sql_read(query, named_params) -> rows` возвращает **только** `what/occurred_on/source_url/status`. `post_json(url, json_body) -> response` (только allowlisted домен и endpoint, при интеграции ограничить timeout, retries, размер ответа). `search(query) -> [{title,snippet,url,origin_url?}]`, максимум две поисковые строки и до пяти lead на каждую. `verify_primary(candidate, lead, document)` проверяет буквальную цитату в переданном тексте первоисточника, число непосредственно рядом с единицей и дату. Документ, дату первого появления, первичность, scope и root_source передает вызывающая система; внутреннего сетевого клиента нет. Для production нужна ещё проверка `first_seen_at` и provenance, которую нельзя имитировать из сегодняшних результатов.

Пример JSON-выдачи при пустой интеграции: `{"candidate_id":"s1","baseline":null,"alternatives":[],"searched":[{"provider":"knowledge.edge","status":"not_connected"},{"provider":"USAspending","status":"not_connected"},{"provider":"free_web","status":"not_connected"}],"outcome":"not_found"}`. Это не ложный сигнал и не пустой успешный baseline.

### Новый консервативный контракт

- Запрещено считать `Evidence.metric`, `Evidence.kind` и `Evidence.unit`, скопированные из `Candidate`, подтверждёнными признаками источника. В `verify_primary` тип измерения выводится из явно найденной конструкции: физический выпуск vs контракт; rate (per year, every year, /year), cumulative (total, to date), point_in_time. Невозможно однозначно установить вид или предмет измерения: `needs_verification`, не `found`.
- Для количественного выпуска ракет требуется прямое обозначение ракет/ESSM/interceptors и действие производства/поставки. Число выпуска грузовиков не подтверждает missile_output. Для contract_value требуется действие заключения контракта и явное слово contract. Неподдерживаемые типы метрик, включая агрегированный федеральный расход без проверяемых строк, остаются кандидатами.
- Субъект определяется проверкой полного написания имени/алиаса **на границе слова** и присутствия связанного с ним действия; соседнее противопоставление `unlike` не делает упомянутую компанию действующим лицом. Нечёткое совпадение BAE ≠ Baekeland. Это ограниченный синтаксический фильтр, **не универсальный парсер языка**: сложные грамматические конструкции должны отклоняться.
- Отрицания (`not delivered`, `never`, `failed to`) и модальность (`hopes`, `plans`, `targets`, `forecast`, `will`, `would`, `could`, `expects`) блокируют подтверждение наблюдаемого факта. Источники, сообщающие только о планах, полезны как leads, но не как наблюдавшийся baseline.
- Парсер сумм поддерживает указанные явно `$41.6 million` → `41600000 USD` и обычные обозначения тысяч/миллиардов. Парсер дат распознаёт `YYYY-MM-DD`, `March 5, 2026` → `2026-03-05` (`date_precision=day`), `March 2026` → `2026-03` (`date_precision=month`). Значение с месячной точностью не получает придуманного дня; исторический cutoff принимает его лишь если **весь месяц** не позже `as_of`. Формулировка `about`/`approximately` сохраняется как `approximate=true`.
- SQL теперь ставит записи, где найдено имя/алиас компании, **перед** записями только с общими словами метрики (`ORDER BY CASE WHEN what ILIKE ANY(names) THEN 0 ELSE 1 END`). Это снижает риск вытеснения значимой строки из `LIMIT 20`, но не заменяет оценку реального плана запросов.
- Внесены восемь точных случаев Claude в регрессионный тест, включая шесть отрицательных и два положительных, а также проверка приоритета SQL и тест недопустимого угадывания дня месяца.

### Пределы доказательности

Проверка реализована только для явных англоязычных конструкций, которые покрывает этот контракт; любые другие языки, подразумеваемые единицы, сложные придаточные, разные величины в одном предложении и спорная первичность требуют `needs_verification`. Признаки `primary`, `first_seen_at`, `root_source` и `scope` по-прежнему доверяются поставщику документов и требуют отдельной независимой проверки. Формальный знак `found` не означает, что модель приняла сигнал или что найдены два независимых источника.

**Статус запуска:** Claude запускал 20/20 предыдущих offline-тестов до этих изменений. Текущий обновлённый набор содержит **25 тестовых методов**, один из них параметризован восемью случаями; полный обновлённый набор ещё не запускался. Live-проба на C4-02/ESSM остаётся за Claude. GitHub Actions, БД, USAspending и сторонние сервисы не запускались и не подключались. PR остаётся draft.

### Новый контракт без инфраструктурных подключений

- `discover(..., propose=None)` по умолчанию сохраняет строгий режим без модели. Опциональный `propose(candidate, document) -> list[Proposal]` предоставляется извне. Модуль **не выбирает модель, не подключает API, не использует ключи, не делает HTTP**. Передаваемые статьёй инструкции считаются недоверенным текстом: модель не принимает решения о `verified`.
- `Proposal` содержит `value`, `unit`, `kind`, `stage`, `organization` (исполнитель действия), `speaker`, `quote`, `date_text`, `is_estimate_or_forecast`, `metric`. Некорректный тип или структура отклоняются. До десяти предложений на один вызов; один вызов `propose` на документ и не более `max_verifications` проверенных документов (по умолчанию 8) на кандидата.
- `PrimaryDocument` дополнен полями `published_at` (ISO дата публикации) и `title`, при этом старые поля сохранены. Именно `published_at`, а не дата события, нужна для `last year` и `this year`; без даты публикации относительный год не принимается.
- `verify_proposal` проверяет, что предложенная цитата **буквально присутствует** в полном тексте; число подтверждено в цитате совместно с единицей, тип величины подтверждён текстом, предмет связан с метрикой, дата выражена в самой цитате, затем проверяется срез `first_seen_at <= as_of`. Месяц и год не превращаются в день: `date_precision` сохраняет `day/month/year`; сравнительная дата для неполного периода берётся консервативно как конец периода.
- `over 400`, `more than`, `at least` отмечаются `lower_bound=true`, `about/approximately` отмечаются `approximate=true`. Точный размер выпуска из нижней границы не выводится. Показатель может использовать нижнюю границу только если это разрешено контрактом последующей аналитики.
- `we/our` принимается **лишь** если текст того же абзаца явно связывает говорящего с организацией, например `Raytheon vice president Jane Roe` или `Jane Roe, vice president of Raytheon`. Совместного упоминания имени и компании без такой связи недостаточно. Для `essm_output` программа ESSM должна присутствовать в заголовке или абзаце.
- Аналитические оценки, прогнозы, планы, цели, производственная мощность и отрицания не становятся подтверждённым фактом, даже если модель ложно предлагает `is_estimate_or_forecast=false`. Сообщения за незаконченный текущий год не трактуются как полный годовой итог.
- Детерминированный `verify_primary` также дополнен запретом на `analysts estimate`; исправление необходимо для **строгого** режима без `propose`.

### Офлайн-проверки и границы

Добавлены проверки с **поддельной функцией `propose`**, без сетевого клиента: восемь прежних кейсов с намеренно ошибочными предложениями модели; аналитики; цитата не из текста; неверное число; инструкция для модели, встроенная в документ; вымышленная статья в форме ESSM с `We produced over 400 missiles last year`, `this year`, `North Star`; отсутствие даты публикации; отсутствие подтверждённой роли говорящего; подмена программы ракет общим выпуском; верхний предел и однократность `propose`. Текст настоящей статьи Seapower **не копировался** в тесты.

**Что запускалось:** по сообщению Claude до правок пройдено **25/25** предыдущих тестовых методов; это не проверка текущего кода. GitHub connector позволил прочитать/обновить файлы, но из локальной среды Python нет сетевого доступа для загрузки актуальной ветки (DNS и прямое соединение не работают). **Новый полный набор тестов в этой сессии не выполнялся, результат PASS/FAIL неизвестен.** Настоящую статью ESSM, группы C4-02 и сопоставимость дат проверяет Claude после возвращения.

**Остаточное ограничение:** наличие в документе цитаты, имени компании, даты и роли говорящего не доказывает подлинность источника или авторитетность высказывания; `first_seen_at/root_source/scope` и статус первоисточника остаются внешними утверждениями. Результат `found` не разрешает автоматическую публикацию сигнала. При следующем провале следует выполнить условие остановки, а не бесконечно наращивать текстовые эвристики.
