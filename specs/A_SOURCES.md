## a1.source-discovery (A1SD)

**1. Назначение.** Непрерывно находить кандидатов в источники так, чтобы росло покрытие по сетке «страна × тип × язык».

**2. Входит.** Поиск по каналам:
- ссылки и названия изданий в уже собранных материалах;
- сайты компаний из B3CL: страницы новостей, пресс-релизов, ленты;
- каталоги и подборки лент по оборонной теме;
- национальные порталы закупок и грантов по странам из географии;
- сайты отраслевых ассоциаций и выставок (они же источники списков для B1CD);
- адресные поисковые запросы по пробелам покрытия.

**Не входит.** Проверка доступности, оценка темы и качества, подписка, сбор материалов.

**3. Вход.**
- `coverage_gap` из D3QM: страна, тип, язык, насколько недобор;
- `company.website` из B3CL;
- `outbound_link`, `mentioned_outlet` из C2EL;
- стартовый набор адресов и запросов.

**4. Выход.** `source_candidate`: `url`, `host`, `guessed_type`, `guessed_country`, `guessed_language`, `found_via` (канал и ссылка на вход), `found_at`. Статус: `new`.

**5. Правила.**
- Источник — любое место постоянных сообщений об оборонке: лента сайта, раздел новостей, Telegram-канал, профиль в соцсети, реестр, база. Список видов открытый: новый вид добавляется без переделки модуля (USER 13.11).
- Упоминание издания, канала или профиля в уже собранном материале — повод найти его и проверить как кандидата (USER 13.11).
- Источники по финансам и инвестициям ищутся так же, отдельной строкой покрытия (USER 13.11).
- Адрес приводится к каноническому виду; один хост и раздел — один кандидат.
- Перед выдачей сверка с A3SL, включая отклонённые и спящие. Отклонённый предлагается повторно не раньше чем через 90 дней (предложение).
- Приоритет каналам и запросам, закрывающим самый большой пробел покрытия.
- Предел кандидатов за цикл задаёт D2RC, чтобы не завалить A2SA.
- Решения: AUTO. Кандидат — не решение, человеку не показывается.

**6. Владельцу.** Ничего.

**7. Сбои.** Недоступен канал поиска — канал пропускается, причина в журнале, остальные работают. Пустой цикл при непустых пробелах — жёлтый статус в D3QM.

**8. Ограничения.** Только бесплатные средства поиска; пределы запросов на цикл; robots; языки — все языки географии, определение языка по странице.

**9. Мера.** Доля кандидатов, принятых A2SA: не ниже 30% (предложение). Вклад в покрытие: число закрытых клеток сетки за цикл.

**10. Готовность.** Три цикла подряд: кандидаты минимум по 10 странам и 5 типам, порог меры взят, повторов уже известных адресов нет.

**11. Петли.** П1, П2, П4.

**12. Существующее.** Четыре еженедельных запуска пишут списки в артефакты, их никто не забирает: Source Hunter 1000, Discovery Chain, Directory Source Leads (падает 5 раз из 7), Inoreader Expanded Discovery. Код: `collectors/source_registry/discovery/` (`radars.py`, `harvest.py`, `collectors.py`). Каталог от 24.10: 68 подключённых, 30 новых, 106 спорных каналов.

**13. Готовый код.** Обязан уметь: по названию издания, организации или канала находить место, где оно постоянно публикует новости и сообщения (лента сайта, раздел новостей, Telegram-канал, профиль в соцсети); извлекать со страницы ссылки и упоминания изданий; искать по запросу без платного ключа. Не требуем: оценки темы, подписки. Соцсети и упоминания — поле для разработки, а не закрытый перечень (USER 13.11).

**14. Решено и открыто.** Решено USER 13.11: средства поиска ставятся в очередь из бесплатных, при отказе одного берётся следующий; перечень бесплатных средств и моделей, включая китайские, составляется на этапе поиска готовых решений. Открыто: какие из них стабильны (GDELT отвечал отказом 05.11); как получать Google Alerts без ручной работы; как читать соцсети в рамках их правил.

## a2.source-approval (A2SA)

**1. Назначение.** По каждому кандидату принять решение «принять, отклонить, спорный» и назначить тип и способ доставки.

**2. Входит.** Проверки, классификация, решение, запись причины. **Не входит.** Поиск, сбор материалов, слежение за здоровьем после принятия.

**3. Вход.** `source_candidate` из A1SD; возврат на перепроверку из A6SH.

**4. Выход.** `source_decision`: `decision` (`accept`, `reject`, `disputed`), `reason_codes`, `type`, `delivery`, `country`, `language`, `checks` (результат каждой проверки), `sample_items` (до 5 заголовков с датами). При `accept` — запись в A3SL.

**5. Правила.** Проверки по порядку, первая непройденная останавливает:
1. адрес отвечает; перенаправление не уводит на чужой сайт;
2. robots и условия разрешают чтение;
3. найден способ доставки: лента, API или разбираемая страница;
4. язык определён;
5. страна определена и не исключена;
6. не дубль записи A3SL (по хосту, по адресу ленты, по совпадению материалов);
7. материалы свежие: есть публикация за последние 60 дней (предложение);
8. тема: доля материалов об оборонке не ниже 20% для `media`; для `procurement`, `grants`, `company_registry` тема проверяется фильтром в A4SC, а не здесь.

Решение: AUTO при прохождении всех проверок; AUTO-отказ при провале 1, 2, 5, 6; BATCH при сомнении в 3, 4, 7, 8. Выборка принятых — SAMPLE.

**6. Владельцу.** Пачка спорных с причиной и примерами заголовков; выборка принятых для контроля.

**7. Сбои.** Таймаут или временная ошибка — до двух повторов в разных циклах, затем `reject` с кодом `unreachable`.

**8. Ограничения.** Не больше заданного числа запросов на кандидата; тему определяют правила и словари, модель — только при сомнении и в пределах лимита D2RC.

**9. Мера.** На контрольной выборке: доля ошибочно принятых не выше 5%, доля ошибочно отклонённых не выше 15% (предложение). Верность типа не ниже 90% (порог плана; сейчас 60–64%).

**10. Готовность.** Порог взят на 100 размеченных кандидатах; 3 цикла решений без участия человека, кроме пачки спорных.

**11. Петли.** П6 (перепроверка), вход для П1, П2, П4.

**12. Существующее.** `collectors/source_registry/discovery/policy.py`, `policy.proposed.json` (правила приняты, запуск отключён), `classification.py` (C1-02, порог не взят), `inoreader_source_manager.py` (подписка), `rss-validator`. Облачный запуск `source-discovery-cloud.yml`: расписание закомментировано, переключатель выключен. Профили трёх лент пилота C1-01 записаны, подписок нет.

**13. Готовый код.** Обязан уметь: проверять ленту на корректность; читать robots; определять язык текста. Не требуем: решения о допуске — это наши правила.

**14. Решено и открыто.** Решено USER 13.11: источник принимается правилом, одобрение владельца не нужно. Контроль — периодическая независимая проверка всей системы сторонней моделью с читаемым отчётом (D5IA). Открыто: стартовые значения правил приёма, пересматриваются по первым живым данным.

## a3.source-list (A3SL)

**1. Назначение.** Быть единственным списком источников, по которому работают сборщики и считается покрытие.

**2. Входит.** Хранение записи источника, её статусов и истории; выдача списка сборщикам; сверка с внешними подписками. **Не входит.** Решения о допуске, хранение материалов.

**3. Вход.** `source_decision` из A2SA; изменения статуса из A6SH; первичный импорт существующих списков.

**4. Выход.** `source`: `id`, `url`, `host`, `type`, `delivery`, `delivery_config` (адрес ленты, параметры API), `country`, `language`, `status`, `health`, `value`, `first_seen`, `accepted_at`, `last_delivery_at`. Статусы: `candidate`, `accepted`, `active`, `sleeping`, `retired`, `rejected`, `excluded`.

**5. Правила.**
- Один источник — одна запись; ключ — канонический адрес доставки.
- Отклонённые и исключённые хранятся, чтобы A1SD не находил их снова.
- Переходы статусов только через A2SA и A6SH; ручная правка — только через D4OD.
- Раз в цикл сверка с подписками Inoreader: расхождение в любую сторону — запись в журнал и в D3QM.
- Решения: AUTO.

**6. Владельцу.** Сводка: сколько источников по статусам, типам, странам.

**7. Сбои.** Недоступна сверка с Inoreader — список работает, сверка помечается непройденной.

**8. Ограничения.** Данные доступа к источникам хранятся отдельно от списка.

**9. Мера.** Дублей 0; расхождений с подписками 0; у каждой записи заполнены тип, способ, страна, язык.

**10. Готовность.** Существующие три места сведены в одно: файл на 63 строки, таблица `intelligence.sources`, 69 подписок Inoreader; сборщики читают только этот список.

**11. Петли.** Опора для П1, П2, П4, П6.

**12. Существующее.** `local-runtime/experiments/EXP-SOURCE-DISCOVERY-01/SOURCE_REGISTRY_CURRENT.csv` (63 строки), `intelligence.sources`, подписки Inoreader (69 на 11.11), `collectors/source_registry/reconcile.py`.

**13. Готовый код.** Скорее всего не нужен: это таблица и правила. Обязан уметь, если берётся: канонизацию адресов.

**14. Решено.** USER 13.11: главный — наш список; Inoreader — один из способов доставки, для RSS. У каждого источника в списке записан способ сбора.

## a4.source-collection (A4SC)

**1. Назначение.** Забирать материалы из всех активных источников и класть их во входящие в едином виде.

**2. Входит.** Четыре сборщика по способу доставки: `feed`, `api`, `page`, `dataset`; отсев дублей; запись сырого ответа. **Не входит.** Получение полного текста по ссылке (A5TC), оценка, извлечение.

**3. Вход.** Активные записи A3SL с `delivery_config`.

**4. Выход.** `item` во входящих: `id`, `source_id`, `url`, `title`, `published_at`, `fetched_at`, `summary` (если дал источник), `raw` (сырой ответ), `item_kind` (`news`, `tender`, `grant`, `award`, `filing`, `paper`, `list_row`), `collector_cycle_id`. Статус: `new`.

**5. Правила.**
- Один адрес материала — одна запись; повтор обновляет `raw` новой версией, а не создаёт запись.
- Сборщик не решает, интересен ли материал. Тематический фильтр допустим только для широких источников (`procurement`, `grants`, `research`) и задаётся в `delivery_config`.
- Строки списков компаний (`list_row`) идут в B1CD, а не в поток событий.
- Частота опроса по типу источника; общий предел задаёт D2RC.
- Решения: AUTO.

**6. Владельцу.** Ничего.

**7. Сбои.** Ошибка источника — запись в A6SH, остальные источники работают. Изменился формат API или страницы — источник помечается на перепроверку.

**8. Ограничения.** Лимиты Inoreader и открытых API; robots для `page`; пауза между запросами к одному хосту.

**9. Мера.** Доля активных источников, давших материал за свой период; задержка от публикации до входящих; доля дублей во входящих — 0.

**10. Готовность.** Материалы всех четырёх способов доставки приходят в одну таблицу входящих; три дня подряд без ручных шагов.

**11. Петли.** Источник данных для П1, П3.

**12. Существующее.** Пишут в базу: Inoreader Cloud (`collectors/inoreader`, каждые 30 минут, успешно) и TED Daily (`collectors/ted`). Пишут только в файлы: Grants.gov (`collectors/opportunities`), OpenAlex (`collectors/research`). EDF — вручную. Сборщик страниц — Web Monitor, отложен 13.11: 2 из 14 источников дают кандидатов, запись отключена кодом.

**13. Готовый код.** Обязан уметь: разбор лент; опрос API с постраничной выдачей; чтение страницы со списком новостей и выделение ссылок на статьи. Не требуем: извлечения текста статьи.

**14. Решено и открыто.** Решено USER 13.11: способов сбора несколько — Inoreader для RSS, собственный опрос лент и страниц, открытые API, Telegram и соцсети. Источники данных о финансах и инвестициях ищет A1SD. Открыто: какие способы сбора из соцсетей допустимы по их правилам.

## a5.text-capture (A5TC)

**1. Назначение.** Для каждого материала получить полный текст с известным происхождением.

**2. Входит.** Загрузка страницы по адресу материала, выделение основного текста, определение языка, оценка полноты, закрытое хранение. **Не входит.** Перевод, извлечение фактов, публикация текста.

**3. Вход.** `item` со статусом `new` из A4SC.

**4. Выход.** `item_text`: `item_id`, `text`, `text_sha256`, `language`, `completeness` (`full`, `partial`, `none`), `origin_method` (лента, страница, архив), `captured_at`, `reason` при неполноте.

**5. Правила.**
- Проверка соответствия: текст сверяется с заголовком материала. Чужой, смешанный или обрезанный текст получает `title_match` = `mismatch` и дальше не идёт (USER 13.11).
- Нет текста у важного материала — искать ту же новость в других местах: первоисточник (релиз стороны), перепечатки, другие издания. Найденный текст хранится со своим адресом в `alt_source_url` и пометкой, что это другой источник той же новости (USER 13.11).
- Текст берётся в порядке: полный из ленты; страница материала; иначе `partial` из аннотации.
- Текст короче порога (предложение: 600 знаков) — `partial`.
- Платный доступ и закрытые страницы не обходятся; такой материал остаётся `partial` с причиной `paywall`.
- Решения: AUTO.

**6. Владельцу.** Ничего.

**7. Сбои.** Таймаут — один повтор в следующем цикле; затем `none` с причиной.

**8. Ограничения.** robots; предел размера страницы; текст не покидает закрытое хранилище.

**9. Мера.** Доля материалов с `full`: цель 70% (порог плана), сейчас около 50%.

**10. Готовность.** Порог взят на живом дне; причины неполноты посчитаны по видам.

**11. Петли.** Нет; условие для П1 и П3.

**12. Существующее.** `collectors/kb_pilot/fulltext.py`, `body_selection.py`, `collectors/inoreader/body_backfill.py`, `collectors/web_monitor/content.py`. Замер 11.11: из 279 материалов за сутки у 139 текста недостаточно. Замер 13.11 по журналам девяти запусков 8–12.11: из 279–426 материалов окна 130–206 отсеиваются как «текста недостаточно».

**13. Готовый код.** Обязан уметь: выделять основной текст статьи из HTML на разных языках; определять язык; давать основание для проверки «текст относится к заголовку»; находить другие публикации той же новости. Не требуем: обхода платного доступа.

**14. Открыто.** Допустимо ли обращаться к веб-архивам; как определять важную новость, ради которой стоит искать перепечатки (стартовое: материал упоминает известную компанию или программу).

## a6.source-health (A6SH)

**1. Назначение.** Держать список источников живым: вовремя усыплять, снимать и возвращать на перепроверку.

**2. Входит.** Подсчёт здоровья и ценности каждого источника, смена статуса, выдача пробелов. **Не входит.** Поиск замены (A1SD), решение о допуске (A2SA).

**3. Вход.** Журнал доставок A4SC; полнота текста A5TC; число событий, в которые попали материалы источника, из C3EC; число опубликованных материалов из C8SP.

**4. Выход.** Поля `health` и `value` в A3SL; событие смены статуса с причиной; список источников на перепроверку для A2SA.

**5. Правила.**
- `health`: дни с последней доставки относительно обычной частоты источника, доля ошибок, доля материалов с полным текстом.
- `value`: доля материалов источника, дошедших до событий, за 30 дней.
- Молчит дольше трёх своих обычных периодов — `sleeping`; ошибка доступа 14 дней подряд — `retired` (предложение).
- Ценность 0 за 60 дней при живой доставке — на перепроверку темы в A2SA.
- Решения: AUTO; выборка снятых — SAMPLE.

**6. Владельцу.** Сводка за цикл: сколько усыплено, снято, возвращено; выборка снятых.

**7. Сбои.** Нет данных о событиях — ценность не считается, здоровье считается.

**8. Ограничения.** Источник не снимается из-за сбоя нашего сборщика: сначала проверяется, что сборщик работал.

**9. Мера.** Ни один мёртвый источник не числится активным дольше 14 дней; ложных снятий в выборке не больше 5% (предложение).

**10. Готовность.** На прошлых данных модуль верно отмечает паузу Inoreader 03–05.11 как сбой сборщика, а не смерть источников.

**11. Петли.** П6; даёт данные для П4.
