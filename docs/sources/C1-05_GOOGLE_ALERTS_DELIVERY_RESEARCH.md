# C1-05 — Google Alerts и разрешённые поставщики кандидатов: проверка условий

**Дата:** 2026-11-05. **Тип работы:** исследовательская записка, пересмотренная по замечанию Claude к [PR #187](https://github.com/nab0k/bohun-the-field/pull/187#issuecomment-6658876415). **Статус:** только исследование, не подключение. **Критерий карточки** по PROJECT_PLAN.md: «алерты приходят в отбор кандидатов». **Он НЕ выполнен:** нет ни живой доставки, ни доказательства появления записей в отборе.

## Решение по отзыву Claude

**Рекомендация Google News search RSS ОТКЛОНЕНА.** По проверке Claude от 05.11.2026: в `https://news.google.com/robots.txt` для `User-agent: *` стоит `Disallow: /`, без разрешения `/rss`; поле `<copyright>` поисковой RSS-ленты ограничивает её показом в личном ридере для личного некоммерческого использования и запрещает иные применения. **Эти два обстоятельства исключают использование Google News RSS в BOHUN как сервисного поставщика кандидатов.** Это документально зафиксированное замечание ревью; в текущем исследовании прямое открытие Google robots.txt через веб-инструмент возвращало ошибку доступа, поэтому самостоятельная перепроверка двух свидетельств НЕ заявляется. Передавать это ограничение нужно как подтверждённый ревьюером запрет, не как гипотезу о качестве RSS.

**Google Alerts**: официальный Google Search Help описывает создание и редактирование оповещений в веб-интерфейсе. Поддерживаемого публичного API для их автоматического создания не обнаружено. Для RSS-доставки **потребуется первоначально вручную создать оповещение в аккаунте Google**, выбрать соответствующий формат и получить адрес ленты; официальной спецификации RSS или стабильности API нет. Это **отдельный вопрос владельцу**: согласен ли он один раз создать/предоставить RSS Google Alerts? Никаких действий от имени владельца не предпринято, доступ к аккаунту не нужен для этой записки. Источник UI: https://support.google.com/websearch/answer/4815696?hl=en . Доставка по конкретному RSS URL не проверена; не выдаём сторонние описания за контракт Google.

## Главный результат: сравнение по ПЕРВОИСТОЧНИКАМ

Выбираем источники, **предоставляющие данные для повторного использования сервисом без личного кабинета**. Публичные условия использования набора данных и допустимость автоматических HTTP-запросов различаются; наличие свободной лицензии **само по себе не доказывает**, что конкретный endpoint можно опрашивать ботом. У всех кандидатов в этой записке **live fetch и проверка robots целевого API-хоста не выполнены**, поэтому нет разрешения на включение.

### Важное различие: GDELT Project и GDELT Cloud

На https://www.gdeltproject.org/about.html#termsofuse описана открытая лицензия **проектных датасетов**. Другой сервис `gdeltcloud.com` имеет самостоятельные тарифы и условия: https://gdeltcloud.com/data-usage (в частности, Free заявлен для персональной оценки, не production). **Нельзя приписывать GDELT Cloud свободную коммерческую лицензию GDELT Project**, и наоборот. Здесь нет намерения подключать GDELT Cloud или оформлять аккаунт.

**Preflight правило для любого будущего потока:** перед кодом или live-запуском сохранить датированный снимок `robots.txt` **конкретного запрашиваемого hostname** и редиректов, лицензию источника и API-условия; при несовместимости права использования или robots явный BLOCK, при невозможности проверить UNKNOWN/HOLD. Проверка robots не заменяет ToS, право на чтение API не равно праву перепубликации оригинальных статей. Условия, допускающие доступ к собственным данным GDELT/TED/Grants, **не гарантируют** права на копирование полных текстов сторонних publishers.

## Предложенный маршрут будущей проверки (НЕ выполнение)

При явном разрешении владельца отдельный **read-only** этап:
1. **Кандидат №1 GDELT Project**: сначала зафиксировать допустимый документированный формат данных (открытые bulk files вместо неограниченного API), технические пределы и robots на hostname; затем маленькую выборку **метаданных/ссылок** без полного текста сторонних публикаций. Не использовать GDELT Cloud Free в production.
2. **Проверить уже существующие TED и Grants.gov сборщики BOHUN** на доступность результатов и возможность подавать `new publisher/agency/programme candidates` в существующий discovery, без второго сетевого сбора, дублирующего живой конвейер.
3. Метки кандидатов: `origin_channel`, `source_dataset`, `provider_terms_version`, `query_or_batch_id`, `original_url` только если проверен, `publisher_claim`, `observed_at`, `dedupe_reason`, `review_reason`. Не считать supplier или publisher из news-mention автоматически подтверждённым источником. **Все кандидаты REVIEW**, пока не проверена аутентичность и RSS/API первоисточника.
4. Отдельно проверить доступность robots и фактическую доставку, ошибочные/пустые результаты, дубль по canonical article/feed и работу контура кандидатов. **Критерий C1-05**: есть наблюдаемый путь от записи во входе до очереди/реестра кандидатов с provenance, без подписки и без auto-approval.
5. Бюджет будущего пилота и лимит попыток обсуждаются отдельно. Если нет свидетельств доступа, денег, cookies или API-ключа без согласования не использовать. Два неуспешных прогона → STOP по `PROJECT_PLAN.md`.
