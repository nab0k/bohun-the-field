## Предлагаемый дизайн (только проект, без кода)

```text
[C3-04 admission: уже принятый материал]
               |
               v
[Input envelope: material_type, text, source IDs, canonical URLs,
 event IDs, publication/observation dates, source excerpts]
               |
               v
[Deterministic gate: обязательные поля, URL, числа/единицы,
 даты, дедупликация, привязка цитат и provenance]
               |
               v
[Atomic claim extraction: бесплатная модель + строгая JSON-схема]
               |
               v
[Evidence alignment: для каждого claim первоисточник/фрагмент,
 contradiction / supported / insufficient / unavailable]
               |
               v
[Reasoning gate: причинность, масштаб вывода, временной порядок,
 чужой контекст, разделение факта/оценки/прогноза]
               |
               v
[Decision: PASS | REVIEW | BLOCK; список причин + evidence IDs]
               |
               +--> PASS: только разрешение следующему этапу публикации
               +--> REVIEW/BLOCK: удержать, передать человеку/на исправление
```

**Никаких публикаций внутри редактора.** Он возвращает вердикт и audit trail; фактический publisher отдельно проверяет вердикт и полномочия. При ошибке API, таймауте, отсутствующем первоисточнике или невалидном JSON: fail closed (REVIEW/BLOCK, не PASS). Для сигналов и аналитики отдельно проверять ссылки на синтезы и базовые факты; чужие аналитические мнения не считать первичными доказательствами. Не смешивать источник, его пересказ и вывод.

### Обязательный контракт проверки

Вход: `material_id`, `material_type` (`synthesis|signal|analysis`), `text`, `event_ids`, `sources[]` с `source_id`, `url`, `published_at`, `retrieved_at`, `excerpt`, `provenance`; `context_items[]` с привязкой к событиям. Отсутствие обязательного поля — REVIEW/BLOCK, не выдумывать значения.

Выход: `decision`, `reasons[]` (`rule_id`, `severity`, `claim_id`, `source_ids`, `explanation`), `claims[]` (`claim_text`, `evidence_span_ids`, `verdict`), `checker_versions`, `model_id`, `checked_at`. Не выводить секреты, скрытые prompt или приватный текст в публичный лог.

### Список проверок (предложение)

| ID | Проверка | Механизм | Если не прошла |
|---|---|---|---|
| E01 | Реальная ссылка, корректный URL и источник в allowlisted evidence | Код + сохранённые provenance | BLOCK при поддельной ссылке; REVIEW при недоступности |
| E02 | Числа, валюта, единицы, проценты, диапазоны и цитаты соответствуют первоисточнику | Извлечение + буквальная/нормализованная сверка | BLOCK при расхождении |
| E03 | Каждое существенное атомарное утверждение имеет релевантный фрагмент | FActScore-подобная декомпозиция + entailment | REVIEW при недостатке, BLOCK при противоречии |
| E04 | Контекст принадлежит тому же событию, компании, программе и периоду | ID/entity/time matching + LLM adjudication | BLOCK при чужом контексте |
| E05 | Вывод не сильнее доказательств; гипотеза маркирована как гипотеза | LLM rubric с цитируемыми spans | REVIEW/BLOCK |
| E06 | Нет дубля того же события (не путать с несколькими независимыми источниками) | canonical event ID + fuzzy matching | REVIEW/BLOCK |
| E07 | Даты публикации, события и прогнозов упорядочены | Детерминированная проверка + temporal LLM | BLOCK при противоречии |
| E08 | Противоречащие источники и неопределённость не скрыты | Сопоставление claims и evidence | REVIEW |
| E09 | Факт, мнение аналитика и прогноз разделены | Типизация claims | REVIEW |
| E10 | Не исполняются инструкции, найденные внутри новостей/страниц | Treat source as untrusted data; delimiter/schema | BLOCK при признаках компрометации |
| E11 | Не теряются обязательные оговорки и география | Сравнение с первоисточником | REVIEW |
| E12 | При сбое модели, исчерпании бесплатного лимита или ошибке JSON публикация запрещена | Fail-closed код | BLOCK/REVIEW |

**Правило:** high-severity E01–E04/E07 -> BLOCK; недостаточность evidence -> REVIEW; PASS только если все обязательные проверки завершились. Один общий score не может перекрыть критическую ошибку. Приоритет проверок: сначала дешёвый детерминированный слой, затем минимальные бесплатные вызовы Groq/Gemini, только по спорным claims; никакого платного fallback без отдельного решения владельца.

## План оценки для C3-10 (не запускался)

1. До разработки зафиксировать размеченный gold set из реальных материалов: корректные синтезы, сигналы, аналитика, а также подложенные ошибки числа, цитаты, URL, чужого контекста, даты, дубля, преувеличенного вывода, скрытого противоречия.
2. Для каждого кейса сохранить ожидаемый `PASS|REVIEW|BLOCK` и rule IDs; разметку подтверждает человек. Не подмешивать gold set в prompt.
3. Отдельно считать recall критических ошибок, false-block/false-review для хороших материалов, precision причин, coverage проверок, latency, число API вызовов и стоимость.
4. **Порог до запуска согласовать с владельцем**: C3-10 требует заранее заданную долю обнаруженных ошибок и максимальную долю ошибочного отсева; в плане конкретных чисел нет. Не выдавать предложенные цифры за утверждённые.
5. Тестировать режимы: модель не отвечает, 429/503, источник недоступен, текст источника содержит prompt injection, несколько источников противоречат, одинаковое событие в разных статьях, отсутствие новых материалов.
6. Начать с offline read-only shadow evaluation. Живые прогоны, подключение и публикация только по отдельным карточкам и разрешениям.
